# 작은 사무실 (work_meta)

담당자에게 업무를 지시하고 보고를 받으며, 서랍에 문서를 보관하는 3D 사무실입니다.
원본 메타버스 전시관의 구조만 참고했고 코드와 에셋은 새로 작성했습니다. 분석 기록은 [docs/rea-analysis.md](docs/rea-analysis.md)에 있습니다.

## 할 수 있는 일

- **공간**: 벽돌 벽과 카펫의 메인 사무실에 5명(총괄·조사·분석·마케팅·기타)이 근무하고, 맨 위에 내 자리가 있습니다. 오른쪽 통로를 지나면 미팅룸입니다.
- **이동과 화면**: 바닥 클릭, WASD로 이동. 끌어서 둘러보기, 휠·핀치·`+`/`-` 버튼으로 확대·축소, `내 근처로` 버튼으로 내 주변을 크게 봅니다. 화면은 공간 경계 밖을 보여 주지 않습니다.
- **화면 배치**: 메뉴, 화면 도구, 대화창은 손잡이(⠿)를 끌어 옮기고, 두 번 누르면 원래 자리로 돌아갑니다. 메뉴는 `작은 사무실` 제목을 눌러 접고 펼칩니다. 배치는 이 브라우저에 저장됩니다.
- **대화와 지시**: 담당자 가까이 가서 대화창에 말하거나, 담당자를 눌러 지시합니다. 대화 상대가 되면 나와 그 담당자가 같은 색으로 함께 강조됩니다. 혼자 있을 때 말하면 총괄이 키워드로 담당자에게 나눕니다. 결과는 `결과 보고서` 서랍에 자동 보관됩니다.
- **협업**: 지시에 `@담당자`를 쓰면 그 담당자가 먼저 일하고 결과를 넘깁니다. 담당자들은 실제로 동료 자리로 걸어가 전달합니다.
- **회의**: 회의 소집을 누르면 전원이 미팅룸에 모입니다. 패널을 닫으면 자리로 돌아갑니다.
- **서류 캐비닛**: 사무실 오른쪽 캐비닛에 PDF·슬라이드 파일을 올리면 칸에 이름과 함께 놓이고, 눌러서 엽니다. PDF는 앱 안에서 열리고, 슬라이드 파일은 내려받아 엽니다. 구글 슬라이드는 공유 주소로 넣으면 앱 안에서 봅니다.
- **서류장별 구글 드라이브 계정**: 서류장 A·B·C와 오른쪽 캐비닛마다 연결할 구글 계정을 고릅니다(패널의 계정 선택, `다른 계정 추가…`). 고른 계정은 계속 유지되고, 서류장 위 안내판에 계정이 표시됩니다. 기본 계정은 Vercel 환경 변수 `DRIVE_ACCOUNTS`(쉼표 구분, 서류장 순서)로 정합니다.
- **구글 드라이브 저장**: 서랍·캐비닛 패널에서 `드라이브 연결`을 누르면 이후 올리는 파일이 그 서류장 계정 드라이브의 `작은 사무실 서류` 폴더에 저장되고, 연결할 때마다 그 폴더의 파일을 불러옵니다. 서랍 이동·삭제(휴지통)도 드라이브에 반영되고, 이 브라우저에만 있던 파일은 `드라이브로` 버튼으로 옮깁니다. 드라이브 파일은 구글 미리보기로 앱 안에서 열려 슬라이드도 볼 수 있습니다.
- **서류장**: 서랍에 파일과 링크를 보관하고, 웹페이지·PDF·HTML·이미지·텍스트를 앱 안에서 엽니다. 서랍마다 구글 드라이브 폴더를 연결할 수 있습니다.
- **아티팩트 창**: 문서·결과물은 오른쪽 창에 열리고 `전체 보기`(또는 제목 두 번 누르기)로 넓힙니다. Esc는 전체 보기 → 분할 → 닫기 순입니다. 마크다운·HTML·SVG·CSV/TSV·JSON·코드·워드(docx)·엑셀(xlsx)·PDF·이미지·동영상·오디오·웹페이지를 앱 안에서 보고, 텍스트 계열은 `코드` 보기·복사·내려받기를 씁니다.
- **채팅으로 끌어 놓기**: 결과물 말풍선·업무 카드·문서 행·서류 이름표·아티팩트 제목, 바깥의 파일·뉴스 링크·메일/메모 글을 대화창에 놓으면 첨부 칩이 붙고, 다음 지시에 함께 전달됩니다. 바깥 파일은 `기타` 서랍, 링크는 `웹페이지` 서랍, 글은 `메모 - …`로 보관됩니다.
- **일정 관리**: 내 자리 뒤 벽의 판을 누르면 구글 캘린더를 앱 안 창으로 엽니다.
- **앱 연결 문**: 미팅룸 북쪽 벽의 문 3개입니다. 첫 문은 AI4Insurance로 연결되어 있고, 나머지는 문 설정에서 주소를 넣으면 됩니다.

## 공간 추가

`src/world.js`의 `ROOMS`에 한 줄을 더하면 동쪽으로 공간이 이어지고 바닥·벽·통로·길찾기·안내판이 따라옵니다. 가구는 `buildOffice`에 놓습니다.
앱 문은 `DOOR_SPOTS`에 공간과 x 위치로 추가합니다. 사무실 벽에도 둘 수 있고, 순서가 저장된 연결과 맞물리므로 뒤에만 추가합니다.

## 담당자 유형

| 유형 | 실행 위치 | 필요한 설정 |
|------|-----------|-------------|
| 채팅 봇 (Claude) | 서버 | `ANTHROPIC_API_KEY` |
| 내장 분석 앱 | 브라우저 | 없음 (CSV·TSV 통계, 텍스트 요약 수치) |
| 내장 문서 검색 | 브라우저 | 없음 |
| 외부 앱 (웹훅) | 서버 | `WEBHOOK_ALLOWED_HOSTS`에 호스트 등록 |
| 사람 담당자 | 없음 | 업무 보드에서 직접 보고 |

### 외부 앱 연결 규약

서버가 HTTPS로 `POST {"agent":"이름","input":"지시 내용"}`을 보냅니다. 앱은 `{"result":"결과"}` 또는 일반 텍스트로 응답하면 됩니다. n8n, Zapier, 직접 만든 API 모두 연결할 수 있습니다.

## 실행과 배포

```bash
npm install
npm test
npx vercel dev   # /api/agent까지 함께 실행
```

Vercel 환경 변수는 `.env.example`을 참고하세요. `OFFICE_ACCESS_KEY`가 없으면 서버 API는 닫혀 있습니다. 앱의 설정 메뉴에 같은 키를 입력해야 봇을 쓸 수 있습니다.

### 구글 드라이브 연결 준비 (한 번)

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만들고 `Google Drive API`를 사용 설정합니다.
2. `OAuth 동의 화면`을 외부 사용자로 만들고, 테스트 상태라면 `테스트 사용자`에 쓸 구글 계정을 추가합니다. 범위는 `drive.file`(이 앱이 만든 파일만)입니다.
3. `사용자 인증 정보 → OAuth 클라이언트 ID → 웹 애플리케이션`을 만들고 `승인된 JavaScript 원본`에 `https://work-meta.vercel.app`(로컬은 `http://127.0.0.1:4173`)을 넣습니다.
4. 받은 클라이언트 ID(`…apps.googleusercontent.com`)를 Vercel 환경 변수 `GOOGLE_CLIENT_ID`에 넣거나 앱의 `설정 → 구글 클라이언트 ID`에 붙여 넣습니다. 비밀값이 아닙니다.
5. 서류장 기본 계정은 Vercel 환경 변수 `DRIVE_ACCOUNTS`에 넣습니다(예: `a@gmail.com,b@school.ac.kr`). 저장소가 공개라 이메일은 코드에 두지 않습니다. 학교·회사(Workspace) 계정은 관리자가 외부 앱을 막았을 수 있습니다.

## 알려 둘 제한

- 업무와 문서는 브라우저 IndexedDB에 저장됩니다(드라이브에 올린 파일은 드라이브에 저장되고 다른 기기에서도 연결하면 불러옵니다). 구글 로그인은 계정별로 약 1시간 유지되고, 만료되면 다음에 누를 때 로그인 창이 잠깐 뜹니다. 기기 간 공유, 다중 사용자, 실시간 접속 표시는 없습니다.
- 외부 사이트가 임베드를 막으면 뷰어가 비어 보입니다. 이때는 `새 탭에서 열기`를 쓰세요.
- PDF, 이미지 등 이진 파일은 내용을 봇에게 넘기지 않습니다(이름·형식·크기만 전달). 텍스트 계열 파일만 내용이 전달됩니다. 바깥 메일·뉴스는 브라우저가 넘겨주는 링크·글만 받습니다.
- 로컬 pptx는 미리보기가 없어 내려받아 엽니다. 워드·엑셀·마크다운 보기는 CDN 라이브러리를 처음 열 때 불러옵니다.
- Claude 응답은 Vercel 함수 60초 제한에 맞춰 `effort: low`로 호출합니다.
