# 원본 앱 REA 분석 기록

대상: `https://museum3d-sundaypingpong.fly.dev`
근거: 브라우저 시나리오 캡처 Evidence `ev_a0839a7a4edd86672bbbb163b9fba21683a93ec79282a7d802abf3ca202919eb`

## 관찰

- Three.js 0.160(jsDelivr), 빌드 없는 ES 모듈 다수(스크립트 127개), Pretendard 폰트
- 3인칭 카메라, 바닥 클릭 이동, NPC 안내원, 말풍선
- 채팅: 같은 공간 대상, 100자, 2초 간격, 50개 보관
- 채널 메뉴(수용 100/100/10), 닉네임·캐릭터 설정
- 동기화는 WebSocket이 아니라 `/api/presence` HTTP 폴링(`?area=street&chatAfter=N`)
- `/api/account`가 180일 토큰 발급, `/api/health`가 규칙 공개(이미지 12MB, webp 변환, 전시 7일, 모델 20MB)
- localStorage 키: `museum3d-device`, `entry-profile`, `token`, `profile-cache`
- 원격 방문자는 최대 20명 표시

## 추론

- 폴링 방식이므로 소규모 동시 접속을 전제로 한 설계로 보입니다.
- 무빌드 모듈 구조는 정적 호스팅과 작은 API 서버 조합에 적합합니다.

## 미확인

- 서버 코드와 저장소 구조는 관찰하지 못했습니다.
- 응답 본문 165건 중 58건만 캡처했습니다(104건 본문 읽기 실패, 3건 시간 초과).
- 클릭 시나리오는 실행하지 않아 업로드·전시 흐름은 코드 일부로만 확인했습니다.
